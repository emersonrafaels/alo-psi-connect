# Comparador rules

- Keep the Comparador's Visão geral in `src/features/institution/comparator/overview/` (pure rules in `overviewLogic.ts`) and its Análise Integrada in `src/features/institution/comparator/` with scale interpretation bands in `scaleBands.ts`, so the page file stays small and bands have one source.
- Feed the Comparador's Atendimentos page only from the `get_institution_appointments_capacity` aggregate RPC over `institution_service_appointments`/`institution_service_capacity` (rules in `comparator/appointments/appointmentsLogic.ts`, units below 10 consultations hidden), so capacity analytics never expose individual consultations.
- Feed the Comparador's Diário emocional page only from the `get_institution_diary_rhythm` aggregate RPC (rules in `comparator/diary/diaryLogic.ts`; exam weeks inferred from the Provas tag; groups below 10 people hidden), so diary text and identities never leave the database.
- Feed the Comparador's Conteúdos e práticas page only from the aggregate tables `institution_content_theme_weeks`, `institution_trail_progress`, `institution_practice_usage` and `institution_event_usage` (team-readable via RLS; rules in `comparator/contents/contentsLogic.ts`), so the page never reads per-student practice or event rows.
- Feed the Comparador's NED Nacional page from `institution_ned_snapshots` (service-level jsonb per NED and semester, no student data) and store action plans in `institution_ned_action_plans`; median comparisons, quadrants and best-practice candidates live in `comparator/ned/nedLogic.ts`.
- Feed the Comparador's Radar de Permanência only from the `get_institution_permanence` aggregate RPC over student `permanence_responses` (latest answer per student and semester, units below 10 hidden; instrument in `src/features/permanence/instrument.ts`, mapping in `comparator/permanence/permanenceReal.ts`), so individual answers never reach institutions.
